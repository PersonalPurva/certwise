Step 1 - Choosing the problem

  • We first looked at many ideas across Health, Safety, Women Empowerment and Education, and checked each one against Smart India Hackathon problem lists and other hackathons.
  • For every idea we asked three questions: is it a real problem, do existing solutions already solve it, and can we build a working demo in time.
  • We chose our own problem because we live it: in first year, students are told to "do certificates", see ads for ₹9 workshops, and don't know which ones employers value.
  • Later we added role guidance: students are also confused about which job role to pick, and you can't judge a certificate without knowing the role.

Step 4 - What we built

1. Find my role

  • 8 questions; each answer adds points to one or more of 6 roles (Software Developer, Web Developer, Cloud/DevOps, Cybersecurity, Data Analyst, AI/ML).
  • Fit % = points the role got ÷ the most it could get. Shows the top 3 roles.
  • Role report: what the job is, college subjects that matter, skills to learn next, a mini project, demand in the market and fresher salary - each with a source link.

2. Check a certificate

  • Type any name - typos are fine ("secuirty plus" finds CompTIA Security+). We use edit distance (Levenshtein, dynamic programming).
  • 5 checks, 0-2 points each, shown in a table with the reason for every point.
  • Verdict: Worth it / Think twice / Skip, plus hard stops: Not yet (needs work experience), Not available (exam closed), Not for this role.
  • Better picks: recognised certificates for the same role that score "Worth it", cheapest first.

3. Check an ad

  • Paste any ad or WhatsApp message. 8 regex rules look for pressure tactics: urgency, tiny prices, "bonus worth ₹15,000", job guarantees, earning claims, speed promises, brand-name tools, crowd claims.
  • Each warning shows the exact phrase found and why it matters. The job-guarantee rule links to the CCPA guidelines on misleading ads.

Step 6 - Keeping data up to date without fake information

Decisions:

  • We first planned to collect job posts by hand. We dropped this: it is slow and goes out of date.
  • We wanted the data to stay current automatically, the way AI tools search the web, but with no made-up numbers.
  • We looked at RAG (retrieval-augmented generation) and decided it was not needed yet: CertWise asks fixed questions (salary for role X, price of certificate Y), so a scheduled, fact-checked refresh is cheaper and safer than generating answers for every visitor. RAG would make sense only if we add a free-text "Ask CertWise" chat.

How the monthly refresh works:

  1. Search and read - once a month, GitHub Actions runs refresh/refresh.mjs. It asks Claude (with web search and web fetch) for each role's salary, demand and skills, and each certificate's price, status and demand - every fact with its URL and an exact quote.
  2. Fact check - refresh/verify.js downloads the page itself and keeps a fact only if the quote is really on the page, every number in the fact is inside the quote, and (for demand) the quote names the certificate.
  3. Publish - verified facts go to data/live.js with the date. Facts that fail are dropped and listed in refresh/report.json. If a fact fails this month, last month's verified fact is kept.
  4. Show - the app shows each live fact with its quote, link and check date.

Status: the refresh code is built and tested (dry run). The first real run needs an ANTHROPIC_API_KEY repository secret; until then the app clearly says "not refreshed yet" and uses the hand-checked facts below.

Step 8 - Testing

  • 46 automated tests (npm test): search and typos, whole-word matching, every verdict type, demand scoring from live data, the fact checker, alternatives, the ad scanner, that every role can win the quiz, and edit distance.
  • Browser checks on phone and laptop sizes, with no console errors.
  • Bugs found and fixed:
    • The "earning claim" rule matched "Learn 20 tools" - now it needs "earn" plus a money amount.
    • The "brand tools" rule flagged official vendor ads - now it needs a "tools" context.
    • "AI tools workshop" wasn't found by search - added keywords to certificates.
    • NPTEL showed up as the "better pick" for every role - general certificates are now left out of role alternatives.
    • Added the "Not for this role" verdict so a cloud certificate isn't called "Worth it" for a data analyst.
  • Security: pasted text is escaped before it is shown (no XSS); no login and no personal data stored.
